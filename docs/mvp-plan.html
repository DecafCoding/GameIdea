MVP Plan — GameIdea (working name)

A web canvas where a game developer draws game concept cards. Each card shows random cues, and the developer rotates the card to choose one cue. A Hook Card reads a stack of cards as a one-sentence game hook.

Plan written 2026-11-01 from the /dev-initial-interview run. Prior art: docs/competitive-scan.html, prepared 2026-11-01. The scan is current. Concept source: concept.md.

GameIdea is a separate app in its own repository. It starts from a copy of the TheForge code and structure (the user's story-card app, at ~/repos/theforge). This plan states every carried-over behavior in full, so it does not depend on the TheForge documents.

Problem and users

Main user

The main user is a solo or hobby game developer, or a game jam entrant. This user needs a game idea that is small enough to build. The app does not target studio designers or tabletop designers.

Problem

The scan in docs/competitive-scan.html shows these problems with current game idea tools:

  • Random word-list tools give nonsense combinations. AI tools give generic, familiar ideas.
  • Most tools give a list of words and stop. The user must still turn the words into an idea.
  • Saving a result needs an account or paid credits. The free tools save nothing.
  • The user cannot aim the draw. One comparable cannot filter by genre at all. Category lists mix genre and art style.

What "solved" means

One session gives the user a hook. A hook is one or two sentences that make a person want to play the game. The user draws cards, tucks them under a Hook Card, and the stack reads as the hook. The user copies the hook with one click, or edits it in a note on a saved board.

The MVP has 11 decks and the Hook Card. The deck list comes from concept.md.

Core loop

  1. The user clicks a deck button in the left rail. The app draws one card of that deck onto the canvas.
  2. The card shows random cues from the deck's pool, on a ring around a round center icon. A 4-cue card has one cue on each edge. A 2-cue card has one cue on the top half and one on the bottom half.
  3. The user points at the card, and its rings show. A click on the left or right half of a ring turns its cues one step. R turns the outer ring, or the only ring. Shift+R turns the inner ring. The card body and the center icon stay still. The cue at the bottom edge, right side up, is the active cue.
  4. The user draws a Modifier from the Role, Resource or Setting Modifier deck, and drops it on a Player Role, Resource or Setting card. A modifier from any of the 3 decks fits any of the 3 cards. Its adjectives become a second ring, and each edge shows an adjective and noun pair. A second Modifier can sit on top of that card as its own card.
  5. The user draws a Hook Card from the top of the rail. The user tucks a Player Role under it, then tucks the other cards below. Tuck means one card sits partly under another card, and the two cards are joined.
  6. Connector badges on each seam join the stack into a sentence. The Hook Card shows the sentence and updates it after each change.
  7. The user turns rings, locks cards they like, and uses Redraw or Redraw All until the hook is good.
  8. The user clicks Copy on the Hook Card, or writes a final version in a note.

Example hook from one stack: "You are a reanimated lighthouse keeper who must trade using stolen memories to keep the light on, but the tide rises every night."

Scope

In the MVP

  • The 11 decks in the Decks table, with 4-cue and 2-cue cards as listed
  • The Hook Card: the head of a stack. It shows the stack as a sentence. A menu above it shows on hover, with Copy (plain text to the clipboard), Redraw All and Discard. The sentence is computed each time and never stored.
  • Connector badges with the default words and choices in the Interfaces section. Click a badge to choose another word. A card keeps the chosen word while it fits the pair. "a" or "an" follows the next word.
  • The ring control: rings show on pointer-over, a click on a ring half turns one step, R and Shift+R. The card body and center icon stay still.
  • The Modifier combine on Player Role, Resource and Setting: combine, swap, On Top and Split. 3 Modifier decks (Role, Resource, Setting) filter one pool by targets. A base card holds 1 merged ring and 1 on-top Modifier card. See feature-modifier-decks.html.
  • A lock on each card. Redraw All skips locked cards.
  • Card strip on a selected card: Split, Redraw, Discard and Lock
  • Redraw: a new card of the same deck in the same place. It keeps its tucks, its lock state and, on a combined card, its adjective ring.
  • Discard: the card is deleted. Undo brings it back.
  • Free tuck: any card can tuck under any card, except that a Hook Card cannot tuck under a card. The app shows a hint for the normal place of each deck.
  • Infinite canvas with pan, zoom, place and move
  • Free-text notes with an editable title
  • Genre settings: the 21 genres in the Genres table, on the 4 genre-tagged decks only (Mechanic, Resource, Progression, Constraint). The Genres panel sets the genres of those 4 decks together and one by one. The user can change them at any time. A change affects the next draw only. The other 7 decks ignore genre.
  • A left rail in labeled groups: Hook Card, Core, Modifiers (3 icon buttons), Optional, Genres with its count line, Add note, and Settings at the bottom
  • Settings: Dark or Light mode, Theme color (Orange, Blue, Green), Snap to grid on or off, the Keyboard list and the version footer. The settings apply to every board in the browser. See feature-settings-and-theme.html.
  • Board list with multiple boards: make, open, rename and delete. The New Board dialog asks only for a name.
  • Autosave after each change, a warning when a save fails, and a warning when one board is open in 2 tabs
  • Undo and redo for the open session
  • Export to a text file, which holds each hook, and to a board file. Import of a board file.
  • Cue pools from the user's deck libraries in docs/libraries/. A one-time split of docs/libraries/decks.json makes one JSON pool file for each deck. The split lowercases the first word of each Constraint cue and drops a leading "the", "a" or "an" from each Setting cue. Apart from those 2 rules, it does not change any cue text. After that, the JSON files are the source, and the user edits them directly. In the 4 genre-tagged decks, each cue lists every genre it fits.
  • Desktop browsers only, with mouse and keyboard
  • Local run at fixed ports, and HTTPS on the local network
  • The visual design in design-system.html: the TheForge base (tokens, fonts, dark canvas, shell and card look) with 9 deliberate deviations, the 11 deck colors and icons, and the Hook Card.

Deferred

  • All Top 10 and Other rows in the scan that this plan does not mark as In or Partial
  • A Hook Card that sits apart from its stack and points at it with a line
  • An editable sentence or an "angle" line stored on the Hook Card
  • Comparable shipped games for a hook, for example "X meets Y"
  • AI help to expand a hook
  • Genres beyond the 21 in this plan
  • A Modifier on Mechanic or Mood cards
  • Shared code between TheForge and GameIdea in a common package
  • Server code and a database for the pools and the boards
  • Tablet and touch input
  • A public website on a free host
  • Usage data

Never, not this product

  • A Format filter, deck or tag (platform, player count, session length). Reason: indie developers already know their format, so it does not narrow a draw.
  • A Style filter, deck or tag (art style and view). Reason: indie developers already know their style, and style changes few cues.
  • Copying cue text from other idea generators or card decks
  • A grid size setting. The grid stays at 24 px, because the placement rules depend on it. See feature-settings-and-theme.html.

Rules

  • A draw picks distinct cues from the deck's pool. One card never shows the same cue two times.
  • In the 4 genre-tagged decks, a draw uses only cues that share at least one genre with the deck's current genres. Each of these decks always has at least 1 genre on, so a draw always has at least 10 cues to pick from.
  • In the other 7 decks, a draw uses the full pool. Genre settings do not apply.
  • A Modifier draw uses only cues whose targets include the deck of the button: Role, Resource or Setting. The card stores that deck in modDeck. Each of the 3 Modifier decks has at least 20 cues. The split and a unit test check this.
  • A card stores a copy of its cues. A pool change or a genre change does not change cards on the board.
  • A cue lists every genre it fits. One cue counts toward each of its genres. A cue that fits every genre lists all 21. There is no generic tag.
  • Each of the 21 genres has at least 10 cues in each of the 4 genre-tagged decks. The split checks this, and a unit test checks the pool files on each pull request, so a pool edit cannot break it.
  • A 4-cue ring turns in steps of 90 degrees. A 2-cue ring turns in steps of 180 degrees.
  • A tucked card moves with the card that it is tucked under.
  • The first combine moves the Modifier's ring into rings[1], copies its modDeck to the ring and deletes the Modifier card. A base card holds only 1 merged ring. A swap gives the old adjectives to a new Modifier card beside the card, with the ring's modDeck. On Top sets the second Modifier's onTopOf to the base card. That Modifier stays a card and moves with the base card. A base card takes 1 on-top Modifier. Split moves rings[1] back into a new Modifier card beside the card, with its modDeck. An on-top card stays on top. Each ring keeps its own active cue.
  • Redraw replaces a card with a new card of the same deck. It takes the old card's place, tucks and lock state. A combined card keeps its adjective ring.
  • Redraw All on a Hook Card applies Redraw to every unlocked card in its stack.
  • A Hook Card is always the head of its stack. It cannot tuck under a card.
  • The Hook Card sentence is computed from the stack on each change. It is never stored.
  • Each pool is a separate data file. The pools are not written into the app code.

Hook sentence rules

  • The sentence reads the stack from top to bottom. When 2 cards tuck under one card, they read in order of their place on the canvas, top first.
  • Each card adds its badge word, then its active cue. On a combined card, the active text is the on-top adjective, then the merged adjective, then the noun, for example "tall frozen pilot". A missing part is left out.
  • A deck that the stack does not have is left out. The sentence never shows a blank slot.
  • If the top card is not a Player Role, the sentence starts with that card's badge word.
  • Mood, Twist and Progression start a new sentence.

Lifecycle

  • A board exists until the user deletes it.
  • A card exists until the user discards or redraws it, or deletes its board. A Modifier card also ends when a first combine absorbs it.
  • A note exists until the user deletes it, or deletes its board.

Interfaces

Surface

One web app for desktop browsers. The user uses a mouse and a keyboard.

Screens

  • Board list. Make, open, rename and delete boards. Import a board file.
  • Board. The top bar, the left rail, the canvas, cards, notes, undo, redo and export.

Feedback details: the start guide on an empty board goes away when the first card is on the board. After Redraw All, a green outline marks each new card for 1 second. After Copy, the menu item shows "Copied" for 2 seconds. A board name cannot be empty. With snap on, Alt held while dragging places a card freely.

Left rail

One rail in labeled groups, top to bottom:

  1. Hook Card
  2. Core: Player Role, Mechanic, Resource, Goal, Conflict
  3. Modifiers: 3 icon buttons, Role, Resource and Setting, each with a hover label
  4. Optional: Setting, Mood, Twist, Progression, Constraint
  5. Genres, which opens the Genres panel. A line under it shows the number of genres on in the board row, for example "3 genres", or "All genres".
  6. Add note, which places a new note at the free grid spot nearest the center of the view
  7. Settings, at the bottom, which opens the Settings dialog

Each genre-tagged deck button shows a genre count: its number of genres on. The count is hidden when all 21 are on.

Genres panel

One row sets the genres of the 4 genre-tagged decks together. Below it, Mechanic, Resource, Progression and Constraint each have their own row. The other 7 decks do not appear, because genre does not change their draws. Every listed deck keeps at least 1 genre. A change applies to the next draw only.

Hints and drop zones

  • Normal places: a Player Role under a Hook Card, then Mechanic, Resource, Goal and Conflict in that order. A Modifier on a Player Role, Resource or Setting. The user can still tuck any card under any card.
  • A Modifier over a card with no adjectives combines anywhere on the card. Over a combined card, it shows 2 zones: center to swap, top to add on top. Over a combined card that already has an on-top Modifier, it shows the swap zone only.

Visual design

The visual design is locked in design-system.html, which is the authority for every token, size and screen. The look carries over from TheForge, with 9 deliberate deviations listed there.

The app has 2 modes, Dark and Light, and 3 theme colors. Only the chrome and the accent change. Cards, notes, badges, deck colors and the Hook Card look the same in every mode and theme color, and warnings keep a fixed color. In light mode, selection and focus outlines use the darker accent text color, so they pass contrast. See feature-settings-and-theme.html.

Outputs

  • Copy on a Hook Card: the sentence as plain text on the clipboard.
  • Text file: the cards, hooks and notes of one board, in plain words.
  • Board file: all data of one board, with a format version. The app can import it again.

Inputs

Mouse, keyboard and a board file import. There is no other input.

Architecture

This section holds the outline. /dev-architecture confirms the details and records them in docs/architecture.html.

  • The whole app runs in the browser. There is no server code and no database server.
  • Language and build: TypeScript 6.0.3 in strict mode, built by Vite 8.3.5. Node.js 24 LTS runs the build tools. npm installs the libraries.
  • Libraries, pinned exactly as in TheForge: React 19.3.1, React Flow (@xyflow/react) 12.12.0 for the canvas, Zustand 5.0.16 with zundo 2.3.0 for state and undo, Dexie 4.4.7 on IndexedDB for storage, Zod 4.6.7 to check imported files.
  • Test and code tools: Vitest 5.0.5, Playwright 1.64.1, ESLint and Prettier.
  • Pattern: feature folders. Each feature has one folder with its screen parts, state actions, logic and tests.
  • Screens use hash addresses: the board list at #/, a board at #/board/{id}.
  • The boards save to IndexedDB, one record for each board. The app asks for persistent storage at start-up.
  • The cue pools ship inside the app files, one JSON file for each deck. A one-time split makes them from docs/libraries/decks.json. After that, the JSON files are the source, and no build step reads decks.json or the Markdown libraries.
  • Ports, fixed: 5174 for development, 4174 for the built app, 4444 for HTTPS on the local network. The browser stores boards for each address and port, so the ports must not change. They differ from the TheForge ports, so both apps can run at the same time.
  • There are no external services: no sign-in, no usage data and no AI.
  • The start point is a copy of the TheForge code. The copy is renamed, and the story pools are removed.

Milestones

The biggest risk is that random stacks make weak or nonsense hooks. The scan ranks this as the top complaint in the category. M2 tests it after a short copy step.

M1: Copy and rename

  • Rename the app, the database and the page title to GameIdea. Set ports 5174, 4174 and 4444.

M5: Export and finish

  • A full check of the carried-over features, and HTTPS on the local network.

  • Pass bar: all done criteria pass.

Cue rules

The user writes the libraries. These rules are guidance for the user, and the conversion step reports cues that break them. Pool sizes come from the libraries. The earlier targets of about 150 cues for each core deck and about 80 for each optional deck are guidance only.

  • Use general phrases. Do not use game titles, or made-up proper names from a game or story, for example "Middle Earth". Real places and eras, for example "feudal japan", "mars" or "mythic greece", are fine, because no one owns them.
  • Keep each cue inside its deck's cue form in the Decks table.
  • A Player Role cue names the character only. A multi-word character is fine when every word is part of what the character is, for example "bounty hunter" or "lighthouse keeper". A word that describes the character, for example "amnesiac" or "one-armed", goes in the Modifier deck instead.
  • Cues are bare. They carry no joining words, because the badges supply them.
  • Keep Genre and art style apart. A cue never names an art style as a genre.
  • Do not copy cue lists from other idea generators or card decks.

Done criteria

  • The M2 pass bars pass: at least 16 of 20 cards in each core deck and 20 of 25 in each of the 3 Modifier decks have a usable cue, and at least 12 of 20 hooks are ideas the user would build.
  • All 11 libraries are converted to JSON pool files that match them cue for cue, after the 2 split rules. Per-genre cue counts above the 10-cue floor are not a done criterion. The user tunes them after the app works.
  • The Hook Card shows the correct sentence for a full stack and for each failure case in State and failure. Copy puts that sentence on the clipboard as plain text.
  • A genre change affects only the next draw. Cards already on the board do not change.
  • Redraw All replaces every unlocked card in the stack and leaves locked cards as they are.
  • All 8 Required rows of the scan work in Chrome, Edge, Firefox and Safari on desktop: the 7 In rows in full, and the Partial row (a draw fills a fixed set of concept slots) at the scope the scan states.
  • Every carried-over feature in the Scope section works.
  • The speed and first-load targets pass.
  • An exported board file imports again with no data lost, and the text file holds each hook.
  • The done criteria in feature-settings-and-theme.html pass.
  • One command runs the app at port 4174. Another command serves HTTPS on the local network at port 4444.

Open risks and assumptions

Risks

  • Draw quality. Random stacks can read as nonsense. M2 tests this first with a fixed pass bar. The scan ranks coherence control as the top differentiator. The MVP answers it only with curated pools, genre settings, rotation and lock.
  • Pool work. The user writes 11 libraries, 4 of them with genre tags. This is the largest job in the MVP, and M2 waits for the core and Modifier libraries.
  • Sentence grammar. Some cue and badge pairs can read badly, for example a Mechanic verb after "who must". The cue forms and badge choices reduce this. M2 shows how often it happens.
  • Two codebases. A fix in TheForge does not reach GameIdea by itself. A shared package is deferred.
  • Lost browser data. If the user clears the browser data, the boards are lost. Export is the only backup. Safari can delete site data after a period with no use.
  • App name. "GameIdea" is a working name. Check it before any public launch.

Assumptions

  • The undo history lasts for the open session only. It is not saved with the board.
  • A new board starts with all 21 genres on for every genre-tagged deck. The user did not pick this default. It was the recommended default and stands until the user changes it.
  • Redraw All follows the single Redraw rule, so a combined card keeps its adjective ring.
  • The badge choices other than the defaults were proposed in the interview and can change during M2.
  • Each Modifier cue lists the card types it fits (Player Role, Resource, Setting). The list sets which of the 3 Modifier decks the cue is in. It does not limit the merge: any modifier fits any Player Role, Resource or Setting card. See feature-modifier-decks.html.
