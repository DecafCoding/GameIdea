Feature — Core Loop Card

2026-11-05 · Extends GameIdea (working name), as planned in mvp-plan.html. Written from the /dev-add-feature run. Lands in Phase 9.

Visual authority: design-system.html holds the card look, the icon and the Boards page copy. Where this brief and the design doc disagree on a visual detail, the design doc wins.

Summary and motivation

After the hook and the Details panel are full, the user has a concept. The next design step is the core loop: what the player does again and again, and why. Today the app has no place for it.

This feature adds a Core Loop card to every new One-Pager board. It holds text the user can edit. The text starts as the live loop text, filled from the board's cards, and becomes the user's own after the first edit.

User change 2026-11-05: the read-only top part (the colored live template and its divider) is removed. The card shows only the header and the edit field. The live text still fills the unedited field and still feeds Reset From Cards; with no steps the field shows "Add cards to the Hook" as its placeholder. The card is as tall as its text at its current width, with no 200 minimum, so a resize makes it taller or shorter. Where this brief says "template" below, read "the live text in the unedited field".

The phase also adds 1 line to the Boards page. It tells the user that the ideas they make are theirs to use.

Fit with the existing application

The feature extends the core loop at its end. The user deals or draws a stack, fills the Details panel, then reads and edits the Core Loop card. Every earlier step works as today.

It widens the scan row "Turn the draw into a pitch: hook, stakes and angle". That row stays Partial, because an editable angle line is still left out. It closes the scan row "State that the user owns the generated ideas". It adds to the row "Send a saved idea to a design document", because the text file now holds the loop.

Scope

In this feature

  • A new card type, loop, shown as the Core Loop card. It is 240 px wide and uses the Hook Card style.
  • A new One-Pager board starts with exactly 1 Core Loop card at (680, 96). That is to the right of the Details panel at its default width, with the 56 px gap.
  • The card is free. The user can drag it. Its drop snaps to the 24 px grid like any free card, and Alt skips the snap.
  • Top part: the live template "[Mechanic] → earn [Resource] → [Progression] → to [Goal]". It is read-only and always current. Each filled step shows in its deck color. A missing step is left out.
  • Lower part: an editable text area. It shows the live text until the first edit. After that it shows the stored text, and card changes do not touch it.
  • A card menu with 2 icon buttons: Copy Loop, and Reset From Cards. Reset From Cards shows only when the card has stored text.
  • The text file adds a "Core Loop" section right after the Hooks section.
  • The Boards page help text ends with "Every idea you make here is yours to use, with no credit needed."
  • 1 new vendored Lucide icon, repeat.

Deferred

  • A Core Loop card on Free Form boards.
  • An import step that adds a Core Loop card to an older One-Pager board file.
  • AI help to suggest or improve the loop text.
  • A keyboard shortcut for Copy Loop.

Never

  • More than 1 Core Loop card on a board. The card has no Duplicate and no Discard.
  • A loop card that a ring turn can overwrite after the user edits it.

Data model changes

CARD_TYPES += 'loop'           // DECK_NAME.loop = 'Core Loop'
Card.loopText?: string         // only on a loop card
  absent  -> the edit field shows the live text
  present -> the edit field shows this text; card changes do not touch it
A loop card: rings: [], tuckedUnder: null, onTopOf: null, locked: false, inConcept: false

No migration. The board format stays at version 2. There is no Dexie version(3) and no UPGRADES[2]. The user confirmed that the app is still in test and the test boards are deleted. The change only adds a value and an optional field, so boards and board files made before it still pass the import check.

Rollback: remove the type and the field. A board file made with a loop card then fails the import check of the older app. That is accepted while the app is in test.

Interfaces and contracts

Live template

loopSteps(board) -> { mechanic?, resource?, progression?, goal? }   // features/canvas, pure
  each step: the card in the Hook Card's stack first (reading order, first match),
             else the first chip by z in that deck's Details lane
  a combined Resource card gives its adjective and noun, as cardText does

buildLoopText(steps) -> { parts: { deck, lead, text }[], text: string }   // features/loop, pure
  order and lead words: mechanic "", resource "earn", progression "", goal "to"
  parts joined by " → "; a missing step is left out
  no steps -> parts: [], text: ""

Example: summon → earn clues → hub grows → to finish a week of chores.

The Progression step has no lead word, because Progression cues have mixed forms. When there are no steps, the top part shows the help text "Deal or draw cards to build the loop." The design doc holds the final wording.

Edits

  • The edit field commits when it loses focus, as the note fields do. That is 1 changeBoard, so 1 undo step and 1 save. Typing makes no save on each key.
  • A commit with text the same as the shown text makes no change.
  • A commit with empty or white-space text removes loopText. The field then shows the live text. The card never shows a blank text area.
  • Reset From Cards removes loopText in 1 changeBoard.
  • Redraw All, Deal Stack and ring turns never change loopText.

Menu

  • Copy Loop: copies loopText if present, else the live text. It uses the Copy Hook code and its fallback dialog through @/features/hook. It is disabled when both are empty.
  • Reset From Cards: shows only when loopText is present.
  • Each is a 44 px icon button with an aria-label and a tooltip in Title Case.

The section is left out when the board has no loop card, or when the text is empty.

Card

  • 240 px wide, the Hook Card fill for each mode, no deck edge and no deck tint.
  • Label row: the repeat icon and "Core Loop" in --accent-text.
  • Top part: the live template. Each step's text is in its deck color, in the Details chip style.
  • A thin divider, then the edit field.
  • The height starts at 200 px and grows with the text.

Architecture fit

Outcome 2: it fits, with 1 local exception. No change to architecture.html.

  • hook-sentence: the live text follows the same rule. It is a pure function, computed on each change and never stored.
  • module-layout and import-rules: the new features/loop/ uses features/canvas and features/hook only through their index.ts. Only features/canvas/ imports React Flow. Only features/hook/ calls the Clipboard API.
  • undo-history and save-transaction: each edit and each reset is 1 changeBoard.
  • storage-seam and schema-shape: the loop card is a card in the one board record.
  • clipboard: Copy Loop reuses the Copy Hook path and its fallback.
  • import-checks: the Zod check gets the new type and field.

Exception: board-file-format and schema-versions say that a shape change adds an upgrade step. This change adds a type and an optional field with no step and no version change. The reason: the change only adds, and the app is still in test with no saved boards to upgrade. If a later change removes or renames a field, or must change saved boards, it must add Dexie version(3) and UPGRADES[2] as the decisions say.

Compatibility and rollout

New One-Pager boards get the card. A One-Pager board made before this feature, or imported from an older file, has no Core Loop card. It loads as it is, with no fix. Free Form boards do not change. The feature ships whole in Phase 9 with no flag.

Testing and regression plan

Unit (Vitest)

  • buildLoopText: all 4 steps, each single missing step, only 1 step, and no steps.
  • loopSteps: stack card first, Details chip second, first chip by z, a combined Resource card.
  • newBoard: a One-Pager board has 1 Hook Card and 1 loop card at (680, 96). A Free Form board has none.
  • Edit recipes: a commit stores the text, a same-text commit returns the same board, an empty commit removes the field, and reset removes the field.
  • Redraw All and dealStack do not change loopText.
  • Stack, reading, tuck, drop and Concept code skip the loop card. The hook sentence never reads it.
  • Import check: accepts a loop card, rejects loopText on another card type, accepts a One-Pager file with no loop card.
  • Text file: the Core Loop section is placed after Hooks, and the loop card is not in Cards.

Browser (Playwright)

  • A new One-Pager board shows the Core Loop card. A ring turn updates the template and the unedited field.
  • After an edit, a ring turn updates the template only. 1 Undo removes the edit. Reset From Cards brings the live text back.
  • Copy Loop puts the shown text on the clipboard.
  • The Boards page shows the ownership sentence.

Regression

  • Every existing test passes on both board kinds.
  • Speed, size and privacy targets pass.

Done criteria

  • The template follows every ring turn, redraw and deal within the 100 ms target. Each step shows in its deck color, and a missing step is left out.
  • The edit field shows the live text until the first edit. After that it keeps the user's text.
  • An edit is 1 undo step and 1 save. An empty edit returns to the live text.
  • Reset From Cards and Copy Loop work, and Copy Loop has the fallback dialog.
  • The loop card never joins a stack and never shows in the hook sentence.
  • The text file has the Core Loop section after Hooks.

  • Every existing test passes on both board kinds. Speed, size and privacy targets pass.

Open risks and assumptions

  • Risk: a Details panel widened past its default can cover the Core Loop card. The card is free, so the user can drag it away.
  • Risk: some cue mixes read badly in the template. The user can edit the text below it.
  • Risk: the change has no upgrade step. A later change to the loop card shape must add one.
  • Assumption: the first matching card in reading order is the right source for each step.
  • Assumption: older One-Pager boards without a loop card are test data only.
