1. Executive Summary

GameIdea is a browser-only canvas app that helps a solo or hobby game developer, or a game jam entrant, find a game idea small enough to build. The user draws game concept cards from 11 decks (Player Role, Mechanic, Goal, Conflict, Resource, Modifier, Setting, Mood, Twist, Progression, Constraint). Each card shows several random cues on a ring around a center icon; the user turns the ring to pick the active cue. The user tucks cards under a Hook Card, and connector badges on each seam join the stack into a one- or two-sentence game hook that the user copies with one click.

The competitive scan shows four gaps in current tools: random word lists give nonsense, AI tools give generic ideas, most tools stop at a word list, and saving needs an account or credits. GameIdea answers with curated cue pools, genre filtering on the 4 decks where genre matters, a rotate-and-lock control that lets the user steer a random draw, a stack that reads as a sentence, and local saving with no account and no cost.

MVP goal: in one session the user draws, tunes and copies a hook they would actually build. The M2 pass bar makes this measurable: at least 12 of 20 hooks the user draws are ideas the user would build.

GameIdea is a separate repository that starts from a copy of the user's TheForge story-card app (~/repos/theforge). It keeps TheForge's stack, canvas, storage and look, and replaces the story decks with game concept decks.

2. Mission

Mission: turn a few random, well-made cues into a game hook a developer wants to build, with no account, no cost and no data leaving the computer.

Core principles

  1. Steer the dice, don't just roll them. Rotation, lock, Redraw and genre settings let the user aim randomness rather than accept it.
  2. End at a hook, not a word list. The stack always reads as a sentence. The sentence is computed, never stored, and never shows a blank slot.
  3. The user owns the words. Cues come from the user's own libraries, converted without changing their text. No copied cue lists, no AI.
  4. Local and private. Everything stays in the browser. No sign-in, no usage data, no requests to any other address.
  5. Nothing changes behind the user's back. Cards keep a copy of their cues; genre or pool changes affect only the next draw.

3. MVP Scope

Scope is owned by mvp-plan.html, Scope. This section restates it by category.

Core Functionality

  • 11 decks with 4-cue cards (Player Role, Mechanic, Resource, Modifier, Setting, Mood) and 2-cue cards (Goal, Conflict, Twist, Progression, Constraint)
  • The Modifier deck draws as 3 decks (Role, Resource, Setting) from one pool, filtered by targets — feature-modifier-decks.html
  • The ring control: rings show on hover; a click on a ring half turns it one step; R turns the outer or only ring, Shift+R the inner ring. Card body and center icon stay still. The cue at the bottom edge is active.
  • Modifier combine on Player Role, Resource and Setting: combine, swap, On Top and Split. A base card holds 1 merged ring and 1 on-top Modifier card.
  • The Hook Card: head of a stack, shows the computed sentence, hover menu with Copy, Redraw All and Discard
  • Connector badges with default and alternative words; "a" / "an" follows the next word
  • Lock on each card; Redraw All skips locked cards
  • Card strip on a selected card: Split, Redraw, Discard, Lock
  • Redraw keeps place, tucks, lock state and a merged adjective ring
  • Discard with undo
  • Free tuck (any card under any card, except a Hook Card never tucks under a card), with hints for each deck's normal place
  • Infinite canvas: pan, zoom, place, move
  • Free-text notes with an editable title
  • Genre settings: 21 genres on the 4 genre-tagged decks (Mechanic, Resource, Progression, Constraint), set together and per deck; next draw only
  • Grouped left rail: Hook Card, Core, Modifiers (3 icon buttons), Optional, Genres with its count line, Add note, Settings
  • Settings: Dark/Light mode, Theme color (Orange, Blue, Green), Snap to grid, Keyboard list, version footer — feature-settings-and-theme.html
  • Board list: make, open, rename, delete; New Board asks only for a name
  • Undo and redo for the open session

Technical

  • Autosave after each change; warning on save failure; warning when one board is open in 2 tabs
  • 11 JSON cue pools from a one-time split of docs/libraries/decks.json, with 2 grammar rules (Constraint lead word lowercased, Setting leading article dropped). The JSON files are the source afterwards.
  • Pool floors enforced by the split and a unit test: 10 cues per genre per tagged deck; 20 cues per Modifier deck
  • Design tokens for all chrome colors, with a lint check against hard-coded colors
  • Desktop browsers only, mouse and keyboard

Integration

  • Export to a text file (holds each hook) and a board file; import of a board file as a new board
  • Copy to clipboard as plain text, with a select-and-copy dialog fallback
  • AI help to expand a hook
  • Comparable shipped games for a hook ("X meets Y")
  • Shared code package between TheForge and GameIdea
  • Server code and a database for pools and boards
  • Usage data

Deployment

  • Local run at fixed ports: 5174 (dev), 4174 (built), 4444 (HTTPS on the LAN)
  • GitHub Actions CI on each pull request
  • A public website on a free host
  • Tablet and touch input

Deferred product features

  • Hook Card apart from its stack, pointing at it with a line
  • An editable sentence or stored "angle" line on the Hook Card
  • Genres beyond the 21
  • A Modifier on Mechanic or Mood cards; more than 1 on-top Modifier
  • A "System" mode, more theme colors, a Settings button on the board list, settings that follow the user across browsers
  • Top 10 and Other scan rows not marked In or Partial in the scan

Never, not this product

  • A Format filter, deck or tag (platform, player count, session length)
  • A Style filter, deck or tag (art style, view)
  • Copying cue text from other idea generators or card decks
  • A grid size setting (the grid stays at 24 px)
  • A rule that limits a modifier to its deck's card type
  • Settings stored in a board, a board file or the undo history

4. User Stories

  1. As a game jam entrant, I want to draw a full concept stack in a minute, so that I can start building before the jam clock runs out.
    Example: the user clicks Hook Card, Player Role, Mechanic, Resource, Goal and Conflict, tucks them in order, and reads "You are a lighthouse keeper who must trade using memories to keep the light on, but the tide rises every night."
  2. As a hobby developer, I want to turn a card's ring to choose among its cues, so that I steer the idea instead of accepting the first random word.
    Example: a Mechanic card shows dig, trade, hide and cook. The user presses R twice and "trade" moves to the bottom edge; the Hook Card sentence updates in under 100 ms.
  3. As a developer who knows what I build, I want to limit Mechanic, Resource, Progression and Constraint to my genres, so that draws fit games I can make.
    Example: the user turns on only Roguelike and Deckbuilder & Cards in the Genres panel. The rail shows "2 genres" and a count pill on each of the 4 deck buttons. Cards already on the board do not change.
  4. As a user, I want to add an adjective to a role, resource or setting, so that a plain noun becomes a hook with a twist.
    Example: the user drops "stolen" from the Resource Modifier deck on "memories" — the card reads "stolen memories". Dropping "tall" on the top zone of a merged "frozen pilot" gives "tall frozen pilot".
  5. As a user, I want to lock the cards I like and redraw the rest, so that I keep what works and reroll what doesn't.
    Example: the user locks the Player Role and Mechanic, then clicks Redraw All on the Hook Card. Every unlocked card is replaced in place, keeping its tucks; each new card shows a green outline for 1 second. One Undo brings every old card back.
  6. As a user, I want to copy the hook with one click, so that I can paste it into my notes or a jam submission.
    Example: the user hovers the Hook Card and clicks Copy. The item shows "Copied" for 2 seconds. If the clipboard write fails, a dialog shows the sentence selected for Ctrl+C.
  7. As a returning user, I want my boards saved without an account, so that I can come back to an idea later.
    Example: the user closes the tab, reopens http://localhost:4174, and finds the board in the board list with its cards, notes and view. A board file export makes a backup that imports as a new board.
  8. As a user who works in a bright room, I want Light mode and a theme color, so that the app is comfortable to use.
    Example: the user opens Settings, picks Light and Green. The chrome and canvas turn light at once; cards, badges and the Hook Card look the same. After a reload there is no dark frame.

Technical user stories

  1. As the pool author, I want a pool edit that breaks a floor to fail CI, so that a draw can never come up short.
    Example: the user removes Fighting tags from Progression cues until Fighting has 9. The pool unit test fails the pull request.
  2. As the developer, I want the hook sentence builder to be a pure function, so that every grammar rule is unit-tested without a canvas.
    Example: a test passes a stack of cards in reading order and asserts the exact string, including "a" / "an" and new sentences for Mood, Twist and Progression.

5. Core Architecture & Patterns

Architecture is settled in architecture.html; this section summarizes it.

Pattern — architecture-pattern

Feature folders (Vertical Slice). Each feature has one folder holding its screen parts, state actions, logic and tests. Shared code goes to shared/ only for genuine cross-cutting needs. The whole app runs in the browser; there is no server code and no database server.

Module layout — module-layout

src/
  app/              app shell, the 2 screens, start-up
  features/
    draw/           deck buttons, grouped rail, draw logic (distinct cues), genre filter
    card/           card view, rings, rotate, cue text, lock control, type icons
    canvas/         React Flow setup, pan, zoom, drag, tuck, tuck hints,
                    connector badges and their word rules for the 12 card types
    hook/           Hook Card: sentence builder, Copy and its fallback dialog, Redraw All
    genres/         Genres panel, genre counts on deck buttons
    notes/          free-text notes with editable titles
    boards/         board list: make, open, rename, delete
    export/         text file (with hooks), board file, import and its checks
    settings/       Settings dialog, Keyboard list, footer (feature-settings-and-theme.html)
  shared/
    model/          types: Board, Card, Cue, Note, Pool, Genre, board format version
    store/          the Zustand store with zundo
    storage/        the one storage module: Dexie, persistent storage, 2-tab warning
    pools/          loads the 11 pool JSON files by web address
    ui/             general parts, for example buttons and dialogs
public/
  pools/            the 11 pool JSON files
  icons/            deck icons, the 3 Modifier icons and the Hook Card icon
tests/e2e/          Playwright browser tests

features/settings/ comes from feature-settings-and-theme.html, which fits the existing pattern. Unit tests sit beside the code as *.test.ts / *.test.tsx.

Import direction — import-rules

  • app/ can import features/ and shared/.
  • A feature can import shared/. It uses another feature only through that feature's index.ts.
  • shared/ never imports features/ or app/.
  • Only shared/storage/ touches IndexedDB / Dexie (and, per the settings feature, local storage).
  • Only features/canvas/ imports React Flow. Only features/export/ imports Zod. Only features/hook/ calls the Clipboard API.

Related settled decisions

  • hook-sentence — the sentence builder in features/hook/ is a pure function of the stack in reading order.
  • storage-seam — the rest of the app uses only listBoards, loadBoard, saveBoard, deleteBoard, onBoardChangedElsewhere. The settings feature adds loadSettings, saveSettings, onSettingsChangedElsewhere as a recorded local exception.
  • save-transaction, tab-sync, undo-history, import-policy, schema-versions — see section 8 and architecture.html.

Draw rules (from mvp-plan.html, Rules):

  • A draw picks distinct cues; one card never shows the same cue twice.
  • Genre-tagged decks draw only cues sharing at least one genre with the deck's current genres. Each deck keeps at least 1 genre on, so at least 10 cues are always available.
  • A Modifier draw uses only cues whose targets include the button's deck, and stores it in modDeck.
  • A card stores a copy of its cues. Pool and genre changes never change cards on the board.

6.2 Card and ring control

  • A 4-cue ring turns in 90° steps; a 2-cue ring in 180° steps. The active cue is at the bottom edge, right side up.
  • Rings show on hover. A click on the left or right half of a ring turns it one step. R / Shift+R turn the outer / inner ring.
  • Card strip on selection: Split, Redraw, Discard, Lock. Lock and unlock are each one undo step.
  • Redraw: a new card of the same deck (and same modDeck) in the same place, keeping tucks, lock, merged adjective ring and on-top card.

6.3 Modifier combine

Drop a Modifier onZonesResult
A base card (Role, Resource, Setting) with no merged ringAnywhereMerge into rings[1]; the Modifier card is deleted
A merged base card with no on-top cardCenter: swap. Top: add on top.Swap (old ring becomes a card beside it) or On Top (onTopOf)
A merged base card with an on-top cardCenter onlySwap

Split moves rings[1] into a new Modifier card beside the base card; an on-top card stays on top. Each step carries modDeck so the deck icon survives. Full spec: feature-modifier-decks.html.

6.4 Hook Card and sentence

  • The Hook Card is always the head of its stack; it cannot tuck under a card.
  • Hover menu: Copy (plain text; "Copied" for 2 s; dialog fallback), Redraw All (one undo step; skips locked cards; new cards outlined for 1 s), Discard.
  • The sentence reads the stack top to bottom; siblings under one card read in canvas order, top first. Each card adds its badge word then its active text. On a combined card: on-top adjective, merged adjective, noun.
  • Missing decks are left out — never a blank slot. If the top card is not a Player Role, the sentence starts with that card's badge word. Mood, Twist and Progression start a new sentence.

6.6 Canvas, tuck and notes

  • Infinite canvas with pan, zoom, place and move; 24 px dot grid.
  • Free tuck with hints for normal places: Player Role under the Hook Card, then Mechanic, Resource, Goal, Conflict. A tucked card moves with its parent.
  • Snap to grid (default on) for drops of free cards and notes; Alt held places freely; tuck, combine and On Top drops ignore snap.
  • Notes: free text with editable title; Add note places one at the free grid spot nearest the view center, open for typing.
  • Start guide on an empty board disappears when the first card lands.

6.7 Genres panel

One row sets all 4 genre-tagged decks together; below it, one row each for Mechanic, Resource, Progression and Constraint. Every listed deck keeps at least 1 genre. Changes apply to the next draw only and are not in undo history. A new board starts with all 21 genres on. The rail shows a count line under Genres ("3 genres" / "All genres") and a count pill on each tagged deck button, hidden at 21.

6.8 Boards, save, export and import

  • Board list: make (name only, never empty), open, rename (Enter / Esc), delete (always asks, not undoable), import.
  • Autosave after each finished change; a drag saves once on drop. A small mark shows waiting or failed saves.
  • Export menu: text file (cards, hooks and notes in plain words) and board file (<board-name>.gameidea.json, the BoardRecord with formatVersion).
  • Import always makes a new board; a duplicate name gets "(imported)"; a bad file is rejected with a message and nothing changes.

6.9 Settings and theme

Mode (Dark / Light), Theme color (Orange / Blue / Green), Snap to grid, Keyboard list (R, Shift+R, Ctrl+Z, Ctrl+Shift+Z) and footer "GameIdea <version> · No account. No data leaves this computer." Defaults: Dark, Orange, Snap on. Stored in local storage key gameidea.settings per address and port; applied via <html data-mode data-theme> before first render. Full spec: feature-settings-and-theme.html.

8. Security & Configuration

  • Authentication: none. There are no users or accounts.
  • Configuration: none, and no secrets (local-run). The only user preferences are the Settings record in local storage.
  • Data: boards in IndexedDB, one record per board, per address and port. Port 4174 boards are separate from 5174 boards, so development never touches real work.
  • Privacy and security posture (nfr-targets): no request to any address other than the app's own; no third-party scripts; fonts and icons bundled. A Playwright network test enforces both.
  • Secure context: ports 4174 and 5174 on localhost and 4444 over HTTPS (mkcert certificate in .certs/, git-ignored) allow the Clipboard API and persistent storage.
  • Failure handling (outside-code): IndexedDB failure → warning and export offer; persistent storage refused → works as normal; no BroadcastChannel → no 2-tab warning; pool load failure → error with Retry, boards still open; local storage blocked → default settings with a note.
  • Deployment: local only (local-run). Ports are locked; a busy port stops the command. A public static site is deferred.

9. API Specification

There is no network API. The internal contracts are:

Storage seam (storage-seam, plus the settings exception)

shared/storage
  listBoards()                         → board index rows
  loadBoard(id)                        → BoardRecord
  saveBoard(record)                    → done or error
  deleteBoard(id)                      → done or error
  onBoardChangedElsewhere(handler)     called with a board id
  loadSettings()                       → Settings (sync, defaults on any fault) + canSave
  saveSettings(settings)               → done or blocked
  onSettingsChangedElsewhere(handler)  called with Settings

BoardRecord and board file (schema-shape, board-file-format)

BoardRecord
  formatVersion: 1
  id, name, createdAt, updatedAt
  view:   { panX, panY, zoom }
  genres: { mechanic, resource, progression, constraint: Genre[] }
  cards:  Card[]   { id, type, modDeck?, rings[], x, y, z, tuckedUnder, onTopOf, locked, connector? }
  notes:  Note[]   { id, title, text, x, y, width, height }

10. Success Criteria

MVP success definition

The user draws 20 stacks and at least 12 hooks are ideas the user would build, and every done criterion in mvp-plan.html and both feature briefs passes.

Functional requirements

  • M2 pass bar: at least 16 of 20 cards in each core deck and 20 of 25 in each Modifier deck have a usable cue; at least 12 of 20 hooks are ideas the user would build
  • All 11 pools match their libraries cue for cue after the 2 split rules
  • The Hook Card shows the correct sentence for a full stack and for every failure case in State and failure; Copy puts it on the clipboard as plain text
  • A genre change affects only the next draw
  • Redraw All replaces every unlocked card and leaves locked cards
  • All 8 Required scan rows work in Chrome, Edge, Firefox and Safari (7 In in full, the Partial row at the scan's stated scope)
  • Every carried-over feature in Scope works
  • An exported board file imports with no data lost; the text file holds each hook
  • The Modifier and Settings feature done criteria pass
  • One command runs the app at 4174; another serves HTTPS at 4444

11. Implementation Phases

The phases are the milestones M1–M5 in mvp-plan.html, with design work timed by design-system.html section 16. M2 comes early because draw quality is the biggest risk.

Phase 1: Copy and rename

M1 · estimate: 2–3 days

Goal: a renamed, story-free copy of TheForge running at the GameIdea ports, with the full token set, fonts, icons and shell in place.

  • Copy the TheForge code into this repository; rename app, database (gameidea) and page title; set ports 5174, 4174, 4444
  • Remove story pools, story card types, Setting kinds and kind-based connector rules; drop the copied board-format upgrade steps and restart at formatVersion 1
  • Move every hard-coded chrome color into a token; add the lint check for hex and rgba in CSS modules
  • Full token set from design-system.html (2 modes, 3 theme colors, no switch yet), bundled fonts, Lucide icons and the Hook Card icon in public/icons/, shell at locked sizes
  • CI on GitHub Actions: lint, type check, unit tests, Playwright, size checks

Validation: copied tests pass; the app runs at 4174; a search of src/ finds no TheForge story type names (character, motivation, description) and no Setting kind names; the color lint check passes.

Phase 2: Hook test

M2 · estimate: 1.5–2 weeks

Goal: prove that stacks of core and Modifier cards read as hooks worth building.

  • 11-card stack drag test first; if it fails, amend canvas-library before continuing
  • The split of decks.json into JSON pools for the 5 core decks and the Modifier, with the 2 grammar rules, targets mapping, stable ids and floor checks; pool unit tests
  • New card types and data model (incl. modDeck, onTopOf) and the Zod import check
  • Cards, rings, hover, rotate (click, R, Shift+R), lock, card strip, Redraw, Discard
  • Hook Card with hover menu (Copy with fallback dialog, Redraw All, Discard) and the pure sentence builder
  • Connector badges with the word menu; tuck hints and drag
  • 3 Modifier decks, combine, swap, On Top, Split and the drop zones
  • The grouped rail with the Hook Card button and the Modifiers row; save mark and notices

Validation: the user draws 20 stacks — at least 16 of 20 cards usable in each core deck, 20 of 25 in each Modifier deck, and at least 12 of 20 hooks the user would build. Modifier feature done criteria pass.

Phase 3: Full core pools and genres

M3 · estimate: 3–5 days

Goal: finished core and Modifier pools with genre filtering on Mechanic and Resource.

  • Finished core and Modifier libraries converted to JSON; Mechanic and Resource carry genre tags
  • Genre filter in draws (at least 1 genre per deck; next draw only; not in undo)
  • Genres panel; genre count pills on the tagged deck buttons; the count line under Genres

Validation: every converted pool matches its library cue for cue after the split rules; genre filtering works; every genre has at least 10 cues in Mechanic and Resource.

Phase 4: Optional decks

M4 · estimate: 2–3 days

Goal: all 11 decks drawable.

  • Setting, Mood, Twist, Progression and Constraint pools converted to JSON; Progression and Constraint carry genre tags
  • The 5 optional deck buttons in the Optional group; their badges and sentence rules (Mood, Twist, Progression start a new sentence)

Validation: every converted pool matches its library cue for cue after the split rules; every genre has at least 10 cues in Progression and Constraint.

Phase 5: Export and finish

M5 · estimate: 1 week

Goal: export, settings and theming live; every done criterion passes.

  • Text export holds each hook; board file export and import round-trip
  • Settings record, the 3 storage actions and no-flash start-up
  • Settings dialog, Keyboard list, version footer, blocked-storage note; Light mode and Blue / Green themes live
  • Snap to grid with Alt bypass; Add note; Settings and Add note in the rail
  • Board list and empty board restyled in every theme
  • Full check of carried-over features; HTTPS on the LAN at 4444

Validation: all done criteria in mvp-plan.html and both feature briefs pass; speed, size and privacy targets pass.
