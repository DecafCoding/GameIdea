Feature — Questions Panel

2026-11-05 · Extends GameIdea (working name), as planned in mvp-plan.html. Written from the /dev-add-feature run. Lands in Phase 10.

Visual authority: design-system.html 9.17 holds the panel look, the icon and the 2 messages. Where this brief and the design doc disagree on a visual detail, the design doc wins.

Summary and motivation

The app helps the user make a game hook, a Details panel and a core loop. It does not help the user test that idea. Hard questions about the player, the fun, the risk and the scope find the weak parts of an idea early.

This feature adds a Questions panel to every One-Pager board. The top part shows 1 random question with a Next button and an answer field. Save Answer moves the question and its answer into a list below. The answers are saved on the board and go into the text file.

The questions are 60 original prompts written for this app. The idea comes from question-card decks such as the Deck of Lenses. No text is copied from any of them.

Fit with the existing application

The feature extends the core loop at its end. The user deals or draws a stack, fills the Details panel, writes the core loop, then answers questions about the idea. Every earlier step works as today.

It closes the scan row "Question prompts that test an idea after the draw". It adds to the row "Send a saved idea to a design document", because the text file now holds the answers.

Related docs: mvp-plan.html, prd.html, architecture.html, design-system.html, competitive-scan.html, feature-one-pager-board.html, feature-core-loop-card.html.

Scope

In this feature

  • A Questions panel on One-Pager boards only. 1 panel per board.
  • The panel is joined to the Core Loop card: the same left edge, 240 px wide, a 24 px gap below the card's bottom edge. It moves when the card is dragged or grows. Its place is never saved.
  • Top part: 1 random question, a Next Question button, an answer field and a Save Answer button.
  • Next Question never shows a question already answered on this board. A skipped question does not come back until every other unanswered question was shown.
  • The current question is view state. It is not saved and not in undo. A reload or reopen shows a new random question.
  • Save Answer adds the question and answer to the top of the list. That is 1 undo step and 1 save.
  • The list: newest first. Each answer can be edited in place (commit on blur, 1 undo step) and deleted with a trash button (no dialog, 1 undo step).
  • All answered: the top part shows a message. Next Question and the answer field hide. The list still works.
  • The question pool fails to load: the top part shows an error with Retry. The list still shows and can be edited.
  • A new pool file, public/pools/question.json, with 60 original questions. The user reviews them before the phase ships.
  • The text file adds a "Questions" section right after the Core Loop section.
  • 1 new vendored Lucide icon, message-circle-question-mark.

Deferred

  • A Questions panel on Free Form boards.
  • Question topics or filters, such as only player or only scope questions.
  • Genre tags on questions.
  • A search over the questions.
  • AI help to answer or judge an answer.

Never

  • A Question card type on the canvas. The user chose the panel over a 12th deck.
  • Question text copied from the Deck of Lenses or any other published deck.
  • Answering the same question twice on 1 board.
  • Reordering the list, or changing a saved question's text.

Data model changes

interface Answer {
  id: string
  question: string   // copied from the pool at save time; a pool edit never changes it
  answer: string     // never empty
}
Board.questions?: Answer[]   // One-Pager boards only; newest first; absent = no answers
                             // the last delete removes the field

question.json: { "type": "question", "cues": [{ "id": "question-0001", "text": "..." }] }

No migration. The board format stays at version 2. There is no Dexie version(3) and no UPGRADES[2]. The user confirmed on 2026-11-05 that the app is still in test and saved boards need no migration. The change only adds an optional field, so boards and board files made before it still pass the import check.

Rollback: remove the field. A board file with answers then fails the import check of the older app. That is accepted while the app is in test.

Interfaces and contracts

Pick rule

pickQuestion(pool, answered, seen, random) -> question | null   // features/questions, pure
  candidates = pool questions whose text is not in answered
  none -> null (the all-answered state)
  unseen = candidates not in seen; empty -> seen is cleared, unseen = candidates
  returns 1 random unseen question; never the current question when another exists

seen is view state in the panel. It is cleared on reload and on board change.

Recipes

  • addAnswer(board, question, text): trims the text. Empty text is refused, and Save Answer is disabled while the field is empty. Adds the item at the top. 1 changeBoard.
  • editAnswer(board, id, text): commits on blur, as the note fields do. Same text, or empty text, returns the same board. Empty text keeps the old answer.
  • deleteAnswer(board, id): removes the item. The question can then show again on Next Question.
  • Redraw All, Deal Stack, ring turns and Core Loop edits never change questions.

Panel

  • Header: the message-circle-question-mark icon and "Questions". A count pill "3 Answered" when the list has items.
  • Top part: the question, the answer field (aria-label "Answer"), then Next Question and Save Answer. Both buttons are 44 px tall.
  • List: each item shows the question, then the answer as an editable field. A trash icon button with aria-label "Delete Answer".
  • The panel's place: left = Core Loop card left, top = Core Loop card top + its drawn height + 24. If the board has no Core Loop card, the panel uses the Core Loop card's default place, (680, 96).
  • The panel is not draggable. Cards dropped on it do not tuck, combine or enter it.

Architecture fit

Outcome 2: it fits, with 1 local exception. No change to architecture.html.

  • module-layout and import-rules: the new features/questions/ imports only shared/. The canvas node uses it through its index.ts. Only features/canvas/ imports React Flow.
  • pool-files and pool-load-failure: the question file loads by web address from public/pools/. Its failure shows an error with Retry, as the decks do.
  • undo-history and save-transaction: each add, edit and delete is 1 changeBoard. Next Question is view state and not in undo.
  • storage-seam and schema-shape: the answers live in the one board record.
  • import-checks: the Zod check gets the new field.
  • tab-sync: an answer change saves the board, so the other tab reloads as for any change.
  • nfr-targets: 60 questions add a few KB to the pool budget.

Exception: board-file-format and schema-versions say that a shape change adds an upgrade step. This change adds an optional field with no step and no version change. Phase 9 did the same with Card.loopText. The reason: the change only adds, and the app is still in test with no saved boards to upgrade. If a later change removes or renames a field, or must change saved boards, it must add Dexie version(3) and UPGRADES[2] as the decisions say.

Compatibility and rollout

Every One-Pager board shows the panel, old and new. A board with no answers has no questions field. Free Form boards do not change. The feature ships whole in Phase 10 with no flag.

Testing and regression plan

Unit (Vitest)

  • pickQuestion: skips answered questions, does not repeat a seen question before the cycle ends, clears seen at the end of a cycle, never returns the current question when another exists, and returns null when all are answered.
  • Recipes: add puts the item first, empty text is refused, a same-text or empty edit returns the same board, delete removes the item, the last delete removes the field.
  • Redraw All and dealStack do not change questions.
  • questionsPlace: below the Core Loop card with the 24 px gap, follows a moved card, and uses (680, 96) with no Core Loop card.
  • Pool floor: question.json has at least 60 questions, no empty text and no repeated text.
  • Import check: accepts answers on a One-Pager board, rejects them on a Free Form board, and accepts a file with no field.
  • Text file: the Questions section is placed after Core Loop and before Details, newest first, and is left out with no answers.

Browser (Playwright)

  • A One-Pager board shows the panel below the Core Loop card. A Free Form board shows none.
  • Answer a question: it moves to the list, and Next Question never shows it again. 1 Undo removes it.
  • Edit and delete an answer. Each is 1 undo step.
  • Reload: the answers stay, and a new question shows.
  • Drag the Core Loop card: the panel follows.
  • All answered (with a small fixture pool): the message shows. A delete brings the question back.
  • The question file fails to load: the error with Retry shows, the list still works, and the deck buttons still work.

Regression

  • Every existing test passes on both board kinds.
  • Speed, size and privacy targets pass.

Open risks and assumptions

  • Risk: the questions are weak or too general. The user review in task 1 is the gate.
  • Risk: a long answer list makes the panel very tall. The user can pan. A collapse control is left for later if needed.
  • Risk: a widened Details panel can cover the Core Loop card and the Questions panel. The user can drag the Core Loop card away, and the panel follows.
  • Risk: the change has no upgrade step. A later change to the answer shape must add one.
  • Assumption: 60 questions are enough for 1 game. The pool can grow later with no code change.
  • Assumption: a half-typed answer lost on reload is acceptable.
