Phase 6: Card Themes And Settings Tabs

The following plan should be complete, but validate documentation, codebase patterns, and task sanity before implementing. Pay special attention to naming of existing utils, types, and models — import from the right files.

Phase Description

Phase 6 (M6) comes from the 2026-11-04 design handoff (docs/design-handoff-2026-11-04/), folded into docs/design-system.html. It changes 3 things the user sees:

  1. Card themes. Card faces, tucked faces, the Hook Card fill and the note now follow the mode. In dark mode the cards are dark (#2A2F38). In light mode they stay cream and the Hook Card turns white. The "Hook" label uses the current mode's --accent-text. The theme color still changes only the accent. Badges, rings, center icons and deck colors never change (design 3 deviations 4 and 8, 4.5, 10.9).
  2. Deck tint. Every card and tucked card, on every board and in both modes, gets a 1 px inset edge in its deck card color and a 14% deck-color tint over the face (design 4.4, 9.4, 9.7). The Hook Card has no tint (9.5).
  3. Settings tabs. The Settings dialog is 900 wide and has 2 tabs, Appearance and Genres (9.11). The Genres panel's content moves into the Genres tab (9.10). The tab is disabled when no board is open. The rail loses the GENRES group, the Genres button and its count line (8.2). While the dialog is open, the rail Settings button shows pressed. The Mode help text and the New Board help line change.

It also brings the docs and checks in line with the new theme rule: the Theme bullet in CLAUDE.md, the README, and the color lint (scripts/check-css-colors.mjs).

Checked against the code at planning (2026-11-04):

  • Already there: the full v1 token set in src/shared/ui/tokens.css, selected by [data-mode] / [data-theme]. Every card, Hook Card and note color is read through a token (--card-*, --hook-*, --note-*, --zone-text), so the mode switch needs token values, not component rewrites. Also there: the per-deck --card-type variable on [data-type] (CardView.module.css lines 7–49), the Settings dialog on the shared Dialog (size="settings", 760), the Genres panel on Dialog size="panel", the genre rules (genreRules.ts) and the count pills (GenreCount).
  • Missing: dark-mode card, Hook Card and note values; the white light-mode Hook Card; --note-border, --shadow-hook and --shadow-note; the deck edge and tint; the light-mode Hook label (it is now hard-coded to the dark-mode accent text with 3 /* fixed: */ lines in HookCard.module.css lines 49–61); the Settings tabs; the Genres tab; the disabled state; the pressed Settings button; the 900 width; the new help texts. The browser tests and docs still state the old "cards never change" rule (tests/e2e/theme.spec.ts line 112, tests/e2e/shell.spec.ts lines 76–92, tests/e2e/card-test.spec.ts line 164, CLAUDE.md "Theme", README.md lines 104–105, 120 and 130).

The board format does not change. FORMAT_VERSION stays 1. Nothing new is stored: the Settings tab is view state, and genres keep their v1 place in the BoardRecord. The One-Pager board (Concept panel, chips, board kind, format version 2) is Phase 7 and is not part of this phase.

User Stories

  • As a user who works in dark mode, I want dark cards, a dark Hook Card and dark notes, so that the board is not a wall of bright cream on a dark canvas.
  • As a user who works in light mode, I want cream cards and a white Hook Card with a readable "Hook" label in my theme color, so that the board looks right in daylight.
  • As a user scanning a stack, I want every card edged and tinted in its deck color, so that I can tell the decks apart at a glance in either mode.
  • As a user, I want genres on a tab of the Settings dialog, so that the rail is shorter and a setting I rarely change sits with the other settings.
  • As a user on the board list, I want the Genres tab to say it needs an open board, so that I know where genres apply.
  • As the owner, I want CLAUDE.md, the README, the token test and the color lint to state the new rule, so that later phases do not undo it.

Problem Statement

Cream cards on the dark canvas are too bright, and the user asked for dark cards. Cards of different decks look alike apart from the center icon. Genres take a whole rail group for a setting that is rarely used. Today the code, the tests and CLAUDE.md all pin the old rule ("cards, notes and the Hook Card never change"). So the change must update the tokens, the components, the tests and the house rules together.

Solution Statement

  • Tokens. Keep the v1 handoff body in tokens.css verbatim. Append one "2026-11-04 handoff" section after the existing blocks. It has a :root block with the dark values (the default mode) and a [data-mode="light"] block with the light values, for every token in design 4.5. It adds 3 tokens: --note-border, --shadow-hook and --shadow-note. tokens.test.ts pins every value against a table copied from design 4.5. A new contrast test checks the section 12 figures.
  • Components. The Hook Card takes --shadow-hook and the plain --accent-text label. The note takes --note-border, --shadow-note and radius 12. The card gets the deck edge and tint as a ::before layer over the face. A layer, not the card's own box-shadow, so the drag shadow and the Redraw All outline never remove it.
  • Settings tabs. The shared Dialog gets a tabs slot between the title row and the caption. features/genres gets a GenresTab with the body of the old panel, and GenresPanel goes away. SettingsDialog gets an optional genresTab slot (caption, footer note, content). app/board/BoardScreen fills it. With no slot, the Genres tab is disabled. features/settings never imports features/genres, the same composition pattern Phase 3 used for the count pill.
  • Rail. The Genres group and the GenresButton are removed. The Settings button gets aria-haspopup="dialog" and aria-expanded, and its pressed look keys off aria-expanded="true".
  • Rules. The color lint accepts a /* fixed: */ literal only for a listed reason. It fails any CSS file outside tokens.css that defines a card, Hook Card or note token. CLAUDE.md and the README state the new theme rule.

Patterns to Follow

Mode-selected tokens (src/shared/ui/tokens.css lines 143–160): dark is the :root default, and light overrides it under [data-mode="light"]. A later block of equal specificity wins:

/* Light mode base */
[data-mode="light"] {
  --bg: #F5F3EE;
  --canvas: #ECE9E2;
  ...
}

Per-deck variable (CardView.module.css lines 7–9). The tint reads --card-type, so it needs no per-deck rule:

[data-type='role'] {
  --card-type: var(--deck-role);
}

Light-mode outline rule (CardNode.module.css lines 18–21), for the selected-tab underline:

:global([data-mode='light']) .selected {
  outline-color: var(--accent-text);
}

Slot composition across features (SideRail.tsx lines 62–69, Phase 3). app/ passes one feature's part into another's slot, so features never import each other:

<DeckButton
  ...
  trailing={<GenreCount id={pillId} count={count} />}
  describedBy={showCount(count) ? pillId : undefined}
/>

Module doc comment (every module): a short /** … */ at the top that says what the module is for and cites the design section. CSS modules start with a /* … */ comment, and literal sizes carry /* design 9.x; no token */.

Unit test style (src/features/genres/GenresPanel.test.tsx): Testing Library render / screen / fireEvent. Names follow functionName_condition_expectedResult.

Browser test style (tests/e2e/theme.spec.ts): test.use({ settings: { mode, accent } }) per describe block, then openBoard(page, board) and backgroundRgb / expectRgbNear from ./helpers.
