Phase 9: Core Loop Card

The following plan should be complete, but validate documentation, codebase patterns, and task sanity before implementing. Pay special attention to naming of existing utils, types, and models — import from the right files.

Phase Description

Phase 9 adds the Core Loop card to every new One-Pager board and 1 ownership line to the Boards page:

  • A new card type, loop ("Core Loop"), with an optional Card.loopText. A loop card has rings: [], tuckedUnder: null, onTopOf: null, locked: false, inConcept: false. No format version change, no Dexie version(3), no UPGRADES[2] (the user's recorded local exception: the app is still in test).
  • Placement: a new One-Pager board starts with exactly 1 Core Loop card at (680, 96), right of the Details panel at its default width plus the 56 px gap. It is a free card: drag, snap and Alt work as for any free card. It never tucks, never takes a tuck, never enters the Details panel and never shows in the hook sentence.
  • Live template (top part, read-only, always current): "[Mechanic] → earn [Resource] → [Progression] → to [Goal]". Each step comes from the Hook Card's stack first (reading order, first match), else the first Details chip by z of that deck. Missing steps are left out. Each step's cue text shows in its deck's lane color.
  • Edit field (lower part): shows the live text until the first edit, then the stored loopText, which card changes never touch. It commits on blur as 1 changeBoard (1 undo step, 1 save). An empty or white-space commit removes loopText.
  • Hover menu: Copy Loop (reuses the Copy Hook path and its fallback dialog through @/features/hook) and Reset From Cards (only while loopText is stored). No Duplicate, no Discard.
  • Text file: a "Core Loop" section right after Hooks; the loop card is never a line under Cards.
  • Boards page: the help text ends with "Every idea you make here is yours to use, with no credit needed."
  • Icon: the Lucide repeat icon, vendored.

Behavior authority: docs/feature-core-loop-card.html. Visual authority: docs/design-system.html 9.3 (Boards page line) and 9.16 (the card), reusing 9.5 (Hook Card and its menu), 9.12 (note text style) and 9.15 (Concept lane colors). Older One-Pager boards with no loop card load as they are: no migration, no import fix.

User Stories

  • As a game jam entrant with a full hook and Details panel, I want a Core Loop card that already reads "what the player does, earns, grows and aims for" from my cards, so that I can see the core loop in one line without writing it from nothing.
  • As a solo developer, I want to rewrite that loop in my own words and have my text stay put while I keep turning rings and redrawing, so that my edit is never lost to a card change.
  • As a user, I want to copy the loop and find it in the text file after the hooks, so that it reaches my design document with the rest of the concept.
  • As a new user on the Boards page, I want to read that the ideas I make are mine to use, so that I can build on them without worrying about credit.

Problem Statement

After the hook and the Details panel are full, the next design step is the core loop, and the app has no place for it. The scan row "State that the user owns the generated ideas" is open, and the row "Send a saved idea to a design document" lacks the loop.

Solution Statement

Add loop to CARD_TYPES and an optional loopText, extend the Zod check, and make every stack, drop, placement, Concept, summary and text-file path skip loop cards (tests first, because a wrong skip lets the loop card join a stack or the sentence). A pure loopSteps(board) in features/canvas/reading.ts picks the 4 step texts; a pure buildLoopText(steps) in the new features/loop/ builds the parts and the plain text. newBoard places the card; setLoopText and resetLoopText are Board → Board recipes in features/canvas/boardActions.ts. The view (LoopCard, LoopMenu) lives in features/loop/ and never imports the canvas, as features/hook/ does; a new LoopNode in the canvas wires it to the store and a React Flow NodeToolbar. The text file and the Boards page line close the phase.

Edge Cases

  • A board with only Concept chips (no train): every step comes from chips.
  • 2 Mechanics in the train: the first in reading order wins; after it is discarded the other takes over.
  • An On Top Modifier on the train Resource: its adjective reads first in the step ("tall frozen …"), as cardText does.
  • A user text equal to the live text: no change, so the field keeps following the cards.
  • The user edits while a Deal Stack reveal runs: the draft stays until blur.
  • A Details panel widened past its default covers the loop card: the card stays a free card and can be dragged away (accepted risk).
  • An imported older One-Pager file: no loop card, nothing added.
  • A hand-made file with a loop card on a Free Form board, 2 loop cards or a blank loopText: refused with the existing not-a-board-file notice.
  • Undo across an edit: Ctrl+Z inside the field is the browser's text undo; on the canvas it undoes the committed edit as 1 step.
