Phase Description

Phase 3 (milestone M3 in docs/mvp-plan.html, design-system §16 M3) gives the user control over genre: a Genres panel that sets the genres of the 4 genre-tagged decks (Mechanic, Resource, Progression, Constraint) together and one by one, a genre count pill on each genre-tagged deck button in the rail, and a count line under the rail's Genres button. Genre changes save with the board but never enter undo history, and they change only the next draw.

The PRD's first bullet for this phase ("Finished core and Modifier libraries converted to JSON") was already delivered in Phase 2: architecture pool-files defines one split of all 11 decks, and Phase 2 ran it (see Phase 2 Notes). The genre filter itself is already wired into draws (drawCard with board.genres, all 21 on). So the remaining work is:

  1. Genre model and store: display names for the 21 genres; a setGenres store action that saves but is never an undo step, with undo and redo keeping the current genres.
  2. Genre rules: a pure module in the new features/genres/ for the panel's toggles, the "at least 1 genre per deck" guard and the count text.
  3. Genres UI: the Genres panel (design §9.10), the genre count pill (design §8.2) and the Genres button with its count line (design §8.2), wired into the rail and the board screen.
  4. Verification: browser tests for the panel, counts, persistence, undo and the real-pool filter; a read-only re-check that the pools still match the library cue for cue and every floor holds.

User Stories

Genres panel
As a developer who knows what I build,
I want to limit Mechanic, Resource, Progression and Constraint to my genres,
so that draws fit games I can make.

Rail counts
As a user looking at the rail,
I want to see how many genres each tagged deck uses and how many I picked,
so that I know at a glance my draws are narrowed.

Safe changes
As a user steering draws,
I want genre changes to keep the cards on the board and stay out of Undo,
so that Undo only reverses what I see change on the canvas.

Problem Statement

Every board has all 21 genres on and nothing in the UI can change them, so the genre filter that draws already apply never narrows anything. The New Board dialog even tells the user to "Change them in the Genres panel", which does not exist yet. The rail has no Genres group, no counts, and the store has no way to change genres without making an undo step.

Solution Statement

Add setGenres to the board store next to setView: it replaces board.genres, saves (bumps saveSeq) and stamps updatedAt without recording an undo step, and undo/redo put the current genres back the same way they already keep the current view. A new features/genres/ slice holds pure rules (genreRules.ts), the GenresPanel dialog, the GenreCount pill and the GenresButton. The rail (in app/) composes them: DeckButton gains a generic trailing slot, so features/draw never imports features/genres. The shared Dialog gains a panel size and an optional close (×) button. No board shape change: Board.genres already has its final v1 shape.
