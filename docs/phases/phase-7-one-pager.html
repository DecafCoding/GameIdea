Phase 7: One-Pager Board

The following plan should be complete, but validate documentation, codebase patterns, and task sanity before implementing. Pay special attention to naming of existing utils, types, and models — import from the right files.

Phase Description

Phase 7 (M7) adds a second board kind, the One-Pager board, from docs/feature-one-pager-board.html (behavior authority) and docs/design-system.html 9.15 (visual authority, plus 8.3, 10, 13, 15 and 16). A One-Pager board holds exactly 1 game: 1 Hook Card with a short Hook Train (the stack under it, with today's tuck rules and hook sentence), and 1 Concept panel to the right of the Hook Card for every settled card. The panel groups its cards by deck in lanes (rail order) as small text chips (drop order). Every existing board becomes a Free Form board and behaves exactly as before.

The phase bundles 6 pieces of work, in the order the feature brief's build plan sets (riskiest first):

  1. Board format version 2. Board.kind, Board.conceptWidth?, Card.inConcept; FORMAT_VERSION = 2; Dexie schema version 2 with an upgrade of each saved record; UPGRADES[1] for board files. Tests first.
  2. Zod checks for the new fields and the One-Pager rules (exactly 1 Hook Card, no tucked Concept card, no Hook Card in Concept).
  3. Board kind. New Board asks One-Pager or Free Form. A One-Pager board starts with its Hook Card. Its Hook Card menu has Copy Hook and Redraw All only; the rail Hook Card button is off.
  4. The Concept panel node beside the Hook Card (it moves with it): header, count pill, lanes and chips; drop routing into the lane of the card's deck; Modifier combine on a Player Role, Resource or Setting chip with a hint that names the result ("Stolen Salt"); Redraw All skips Concept.
  5. Chip actions. Pop-out by double-click to an open spot beside the panel; drag a chip out to the canvas or onto a Hook Train card; resize the panel width (232 to 640, saved on release).
  6. Outputs. A Concept section in the text file, a One-Pager label on the board list, and the One-Pager footer "12 cards · 1 hook · 1 concept".

User Stories

  • As a game jam entrant, I want a One-Pager board with 1 Hook Card and a Concept panel, so that I can keep many Resources, Settings, Mechanics and Goals for one game without the hook train growing into a paragraph.
  • As a user, I want to drop a settled card anywhere on the Concept panel and have it land in its deck's lane, so that the page sorts itself.
  • As a user, I want to drop a Modifier on a Player Role, Resource or Setting chip and see the result named before I let go, so that I can build "stolen salt" in place.
  • As a user, I want to double-click or drag a chip back out to a full card, so that I can turn its rings or put it in the Hook Train.
  • As a user, I want to resize the panel and have the width saved, so that long chips have room.
  • As a user with saved boards, I want every board I already have to open unchanged as a Free Form board, so that the update loses nothing.
  • As a user, I want the text file, the board list and the footer to show the One-Pager parts, so that the export reads like a one-pager and I can tell my boards apart.

Problem Statement

A game idea often has more than one Resource, Setting, Mechanic or Goal. Today every card goes into one vertical train under a Hook Card. At about 10 cards the train is too tall to see or edit, and the hook sentence becomes a paragraph instead of a hook. The board format has never changed since version 1, so this is also the first real use of the upgrade path; a mistake there stops saved boards from loading.

Solution Statement

Raise the format to version 2 with 3 fields and 1 shared, pure upgrade step that both Dexie (saved records) and the board file import (UPGRADES[1]) run, so the 2 paths cannot drift. Model the Concept panel as data on cards (inConcept: true, tuckedUnder: null, chip order by z) plus 1 board field (conceptWidth). Its place is derived from the Hook Card, never stored. All rules (lanes, routing, enter, leave, pop-out, combine on a chip, resize) are pure Board → Board recipes in features/canvas/concept.ts, each committed through one changeBoard call: 1 undo step and 1 save. The panel is 1 extra React Flow node (type: 'concept') built from the board on each change. The canvas finds the chip under the pointer with document.elementsFromPoint, because the chips are laid out by CSS wrapping. Stack, reading, drop, placement and Redraw All code skip Concept cards, so the hook sentence builder and every Free Form path stay as they are.

Patterns to Follow

Pure recipe, one undo step. Every user action is a Board → Board function that never mutates its input, committed with one changeBoard (boardActions.ts lines 48–58):

function replaceCard(board: Board, card: Card): Board {
  return { ...board, cards: board.cards.map((c) => (c.id === card.id ? card : c)) };
}
export function placeNewCard(board: Board, card: Card, spot: Point): Board {
  return { ...board, cards: [...board.cards, { ...card, x: spot.x, y: spot.y, z: nextZ(board), tuckedUnder: null }] };
}
// canvas: changeBoard((b) => splitCard(b, id));   A recipe that returns the same board is no step and no save.

Untuck shape to mirror for enterConcept (stack.ts lines 126–132):

export function untuckCard(board: Board, id: string, x: number, y: number): Board {
  const oldRoot = rootOf(board, id).id;
  const z = nextZ(board);
  let next = replaceCard(board, id, (card) => ({ ...card, tuckedUnder: null, z, x, y }));
  if (oldRoot !== id) next = layoutStack(next, oldRoot);
  return layoutStack(next, id);
}

Edge Cases

  • A card with cards tucked under it dropped into the panel: each becomes a chip in its own lane, in stack order.
  • A Modifier with tucked cards combined onto a chip: its tucked cards become chips.
  • A chip with an On Top Modifier: the chip reads "tall frozen pilot"; popping it out brings the On Top Modifier along.
  • A Modifier dropped on a Mechanic chip or on empty panel space: it stays on the canvas where it was released; no outline.
  • A Hook Card or a note over the panel: no hint, a normal move.
  • A chip dragged and released on the panel, or clicked: no change, no undo step.
  • Resize released at the same width: no undo step, no save.
  • A chip double-click: no canvas zoom.
  • A version 1 file with a card that is not an object: upgradeBoardV1 leaves it, and Zod rejects the file.
  • A One-Pager file with no conceptWidth: imports, panel at 232.
  • A loose card placed over the panel area: draws, notes and pop-outs avoid the measured panel; a drop with the pointer over the panel still routes to the panel.
