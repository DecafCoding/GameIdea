Phase 4: Optional decks

The following plan should be complete, but validate documentation, codebase patterns, and task sanity before implementing. Pay special attention to naming of existing utils, types, and models — import from the right files.

Phase Description

Phase 4 makes all 11 decks drawable from the rail. It fills the rail's Optional group with the 4 missing deck buttons — Mood, Twist, Progression and Constraint — after the Setting button that has been there since Phase 1 (design 8.2: "OPTIONAL Setting, Mood, Twist, Progression count, Constraint count"; design §16 M4: "The 5 optional deck buttons fill the Optional group").

Almost everything else the PRD lists for this phase already exists and is verified rather than rebuilt:

  • Pools (done in Phase 2): all 11 pool files in public/pools/ came from the single split of docs/libraries/decks.json; Progression and Constraint carry genre tags; the floor test covers them. Checked again at planning: public/pools/ is unchanged since db0d494 and the in-memory comparison reports MATCH for all 11 decks (setting 279, mood 145, twist 224, progression 352, constraint 222).
  • Model (done in Phase 2): DECKS, CUES_PER_CARD (Mood 4; Twist, Progression, Constraint 2), DECK_NAME, GENRE_DECKS in src/shared/model/index.ts.
  • Card faces and icons (done): TYPE_ICON (smile, rotate-ccw, trending-up, shield-x) in src/features/card/TypeDisc.tsx; the SVGs in public/icons/; deck, rail and ring-hover tokens in src/shared/ui/tokens.css; 1-line Mood labels and the 2-cue frame in CardView.tsx.
  • Badges and sentence rules (done in Phase 2): WORDS in src/features/canvas/connector.ts (It feels / The tone is; Except / The catch:; As you play, / Over time,; with / and) and NEW_SENTENCE = ['mood', 'twist', 'progression'] in src/features/hook/buildHookSentence.ts, with unit tests.
  • Draw and genre filter (done): BoardScreen.draw passes the deck's genres for every GENRE_DECKS member, so Progression and Constraint draws are filtered with no change.
  • Genre pills (done in Phase 3): SideRail adds a GenreCount pill to any genre-tagged deck it renders, so Progression and Constraint get theirs as soon as their buttons exist.

So the real work is 1 constant in SideRail.tsx, plus the tests and docs that prove the 4 decks work end to end from the rail: drawn faces, genre pills, badges and the new-sentence rule inside a Hook Card stack.

User Stories

Optional deck buttons. As a game jam entrant, I want to draw Mood, Twist, Progression and Constraint cards from the rail, so that I can push a hook past the core five with a tone, a catch, a sense of growth or a design limit.

Optional cards in the hook. As a solo developer, I want an optional card tucked into a Hook Card stack to add its badge word and (for Mood, Twist and Progression) a new sentence, so that the copied hook reads as natural sentences.

Genre counts on optional decks. As a user who narrowed genres, I want the Progression and Constraint buttons to show how many genres they draw from, so that I can see at a glance that those draws are filtered.

Problem Statement

The app loads all 11 pools and can render, tuck, badge and read all 12 card types, but the rail only offers 7 decks plus the 3 Modifier buttons. Mood, Twist, Progression and Constraint cards can only appear on a board through an import or the card test page, so the user cannot use 4 of the 11 decks and cannot see the Progression and Constraint genre filters in action.

Solution Statement

Extend the OPTIONAL list in src/app/board/SideRail.tsx to the design's order ['setting', 'mood', 'twist', 'progression', 'constraint']. The existing button() helper already renders a plain DeckButton for Mood and Twist and a DeckButton with a GenreCount pill for Progression and Constraint. Then update the unit and browser tests that pin the rail at 10 deck buttons, add tests that prove the optional decks draw, pill, badge and read correctly, re-check the pools read-only (never rerunning the split), and update the README.
