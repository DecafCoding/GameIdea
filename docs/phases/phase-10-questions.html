Phase 10: Questions Panel

The following plan should be complete, but validate documentation, codebase patterns, and task sanity before implementing. Pay special attention to naming of existing utils, types, and models — import from the right files.

Phase Description

Phase 10 adds a Questions panel to every One-Pager board, old and new, joined below its Core Loop card. It asks hard, original questions that test the game idea, and keeps the user's answers with the board:

  • A new pool file, public/pools/question.json, with 60 original questions in the deck pool file shape ({ "type": "question", "cues": [{ "id": "question-0001", "text": "..." }] }), loaded by web address through its own load and its own failure state. A failed question load never turns off the deck buttons.
  • A new optional field Board.questions?: Answer[] ({ id, question, answer }, newest first, One-Pager only, absent when there are no answers). No format version change, no Dexie version(3), no UPGRADES[2] (the user's recorded exception, as in Phase 9).
  • A pure pick rule pickQuestion: never an answered question; a skipped question does not come back until every other unanswered question was shown; never the current question when another exists; null when all are answered.
  • 3 Board → Board recipes: addAnswer, editAnswer, deleteAnswer, each 1 changeBoard (1 undo step, 1 save). Next Question is view state only.
  • The panel (design 9.17): header with the message-circle-question-mark icon, "Questions" and an "N Answered" pill; the current question, an answer field, Next Question and Save Answer; the answer list with in-place edit and a trash button; the all-answered and load-failed states.
  • The canvas node: placed by a pure questionsPlace from the Core Loop card's place and drawn height (24 px gap), following the card while it is dragged or grows; not draggable, not a drop target, never stored.
  • The text file: a "Questions" section right after Core Loop and before Details.

Behavior authority: docs/feature-questions-panel.html. Visual authority: docs/design-system.html 9.17, reusing 9.15 (Details panel), 9.16 (Core Loop card) and 9.12 (note text). No new token, no new library.

User Stories

  • As a One-Pager user, I want the app to ask me hard questions about my idea, so that I find its weak parts before I build it.
  • As a user, I want to skip a question I cannot answer yet, and never see a question I already answered, so that every question I read is worth my time.
  • As a user, I want my answers saved on the board, editable and deletable, and in the text file, so that they reach my design document with the hook, the loop and the details.

Problem Statement

The app helps the user make a hook, a Details panel and a core loop, but does not help the user test the idea. The scan row "Question prompts that test an idea after the draw" is open, and the row "Send a saved idea to a design document" lacks the answers.

Solution Statement

Ship the 60 questions and their floor test first (the riskiest part). Add Answer, QuestionPool and Board.questions to the model, a hand-written parseQuestionPool plus loadQuestionPool / useQuestionPool in shared/pools/ (separate from usePools), and the Zod rules in features/export/schema.ts. A new features/questions/ holds the pure pickQuestion, the 3 recipes, the useQuestionDeck view-state hook and the QuestionsPanel view; it never imports the canvas (lint block, as for features/loop). The canvas gets a pure questionsPlace, a 'questions' node in toNodes, a QuestionsNode that wires the view to the store, the loop card's measured height through React Flow's useStore, and the follow-during-drag rule mirroring the Details panel and the Hook Card. BoardScreen loads the question pool and passes it to the canvas. The text file gains its section; browser tests and docs close the phase.

    export interface PickInput {
  pool: readonly string[];          // question texts in file order
  answered: ReadonlySet<string>;     // question texts on the board
  seen: readonly string[];          // shown since the cycle began, current included
  current: string | null;
}
export interface Pick { question: string; seen: string[] }
/** null when every pool question is answered. */
export function pickQuestion(input: PickInput, random: () => number = Math.random): Pick | null
    Rule: candidates = distinct pool texts not answered; none → null. others = candidates ≠ current (or all candidates when that leaves none). unseen = others not in seen; if empty, the cycle ends: seen becomes [] and unseen = others. Pick unseen[Math.min(n - 1, Math.floor(random() * n))]; returned seen = the (kept or cleared) seen list filtered to candidates, plus the pick. Never mutates input.

Edge Cases

  • A One-Pager board from before Phase 9 (no Core Loop card): the panel sits at (680, 96).
  • The Core Loop text grows while the panel is on screen: the panel moves down with the measured height.
  • The loop card scrolled off screen (unmeasured or unmounted): the panel falls back to the 200 px minimum height.
  • Undo of a delete in the all-answered state: the message returns; redo frees the question again and the deck picks it.
  • Another tab answers the current question: the board reloads, the current question is now answered, the deck picks another.
  • A pool edit renames a question: the old answer keeps its copied text and the renamed question can show again (accepted; answers match by text).
  • A half-typed answer is lost on reload (accepted in the brief); it survives panning away because the draft lives in BoardCanvas.
  • A card dropped over the panel only moves and paints above it; it never tucks, combines or enters it.
  • A hand-made file with answers on a Free Form board, an empty list or a blank answer: refused with the existing not-a-board-file notice.
