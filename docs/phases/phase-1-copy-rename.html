Phase Description

Phase 1 (milestone M1 in docs/mvp-plan.html) turns the empty GameIdea repository into a renamed, story-free copy of TheForge that builds, tests and runs at the GameIdea ports, with the GameIdea design tokens, fonts, icons and shell in place. It writes no new product feature: every later phase builds on this copy.

It bundles five work items:

  1. Copy the TheForge app, tooling, tests and CI into this repository.
  2. Rename app, database (gameidea), page title, board file extension and ports (5174 / 4174 / 4444).
  3. Strip story code: story card types, story pools, Setting kinds, kind-based connector rules, story genres and the 2-step genre New Board dialog; restart the board format at formatVersion 1 with no upgrade steps.
  4. Tokens: the full GameIdea token set (2 modes, 3 theme colors, no switch yet), every hard-coded chrome color moved into a token, and a lint check that fails hex and rgba in CSS modules.
  5. Shell and assets: bundled fonts, the Lucide icon set and the Hook Card icon in public/icons/, the top bar and rail at their locked sizes, and CI on GitHub Actions.

Problem Statement

The repository holds only planning docs. The architecture (docs/architecture.html) fixes GameIdea's stack, storage, layout and tooling as a copy of TheForge, but TheForge names 5 story types (Character, Motivation, Setting, Conflict, Description), Setting kinds (place, object, event), kind-based connector words, 4 story genres and 5 board-format upgrade steps throughout its code and tests. Its tokens use TheForge names and values, it hard-codes a handful of colors, and it runs on TheForge's ports and database. Left as is, the copy would collide with TheForge and leak story behavior into every later phase (the architecture's top-listed risk).

Solution Statement

Copy TheForge file for file (minus its docs, build output and secrets), then change it in small, always-green steps: rename identity and ports; map the 5 story types one-to-one onto the 5 GameIdea types with the same ring shapes (character→role, motivation→goal, setting→setting, conflict→conflict, description→modifier); remove the story pools and serve fixture pools to the browser tests; remove Setting kinds; replace the connector words with the GameIdea badge table for these 5 types; replace story genres with the 21 GameIdea genres on the 4 genre-tagged decks; restart the format at version 1. A Vitest check then fails on any story type or Setting kind name in src/. Finally, replace tokens.css with the handoff token set, migrate every var(--…), add the color lint, vendor the icons and restyle the top bar and rail to the locked sizes. The other 7 GameIdea card types, hook, modDeck, onTopOf, locked, the pool split and the 200 px card are Phase 2.

if (data.type !== type) {

The other 6 deck types, hook, modDeck, onTopOf and locked are Phase 2 ("New card types and data model"). Authority: PRD Phase 1/2 split + smallest reversible option.
  • ASSUMPTION: Phase 1 ships no pool files. The story pools must go (PRD Phase 1) and the GameIdea pools come from the Phase 2 split, so the built app at 4174 shows the existing "decks did not load" banner with Retry and disabled deck buttons until Phase 2; boards, notes, export and import work. Browser tests get made-up fixture pools through Playwright routing. Authority: pool-files, pool-load-failure, mvp-plan Cue rules (no copied cue lists).
  • ASSUMPTION: The board's genres field takes its final v1 shape now (4 genre-tagged decks, 21 kebab-case genres, all on for a new board), and New Board asks only for a name; the TheForge genre dialog and story genres are removed. Kebab rule: lowercase, drop &, runs of non-alphanumerics become one - ("Builder & Management" → builder-management). The Phase 2 split must use the same ids; genres.test.ts pins them. Authority: schema-shape, pool-files, mvp-plan Data model, PRD §6.8.
  • ASSUMPTION: formatVersion 1 with the Phase 1 card shape is not yet frozen. No user board can exist before Phase 2 ships pools (no deck draws), so Phase 2 may add modDeck, onTopOf, locked and the new types at version 1 without an upgrade step; from the end of Phase 2, any shape change needs an upgrade step. Authority: board-file-format ("stays cheap until the user keeps real boards") + smallest reversible option. Phase 2's planner should confirm.

  • ASSUMPTION: Card geometry stays at TheForge's 250 px card and 59 px tuck in Phase 1 (TS CARD_SIZE, ring geometry, carried-over --card token). The 200 px card and 56 px tuck are design §9.4/§9.7, which design §16 places in M2. tokens.css already holds --card-size: 200px and --tuck-offset: 56px unused. Authority: design-system §16.

These are not new design tokens (no chrome color is invented); they keep copied behavior until Phase 2 and are pinned by an allow list in the test. Authority: design-system §1 (styles.css wins for values), §4–§6.

White on a deck color or on --danger stays as a literal with a /* fixed: … */ marker, matching CLAUDE.md "fails hex and rgba in CSS modules outside card and deck tokens"; no new token is invented for it. Authority: mvp-plan M1, CLAUDE.md Conventions.
